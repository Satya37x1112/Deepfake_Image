# 🚀 Deploying Deepfake Image Detector to Render

This comprehensive guide will walk you through deploying your **Deepfake Image Detector** to [Render](https://render.com) so it is live and accessible on the web!

Since we have already configured the codebase with dynamic ports and routing, deployment is incredibly straightforward.

---

## 📋 Prerequisites

1. **A GitHub or GitLab Account**: You'll need to push this code to a git repository.
2. **A Render Account**: Sign up for free at [render.com](https://render.com).

---

## 🛠️ Step 1: Push Code to GitHub / GitLab

Your directory is already set up and committed locally. Follow these steps to push it to a new remote repository:

1. Create a new **Private** or **Public** repository on [GitHub](https://github.com/new). Do **not** initialize it with a README, license, or `.gitignore` (we already have them!).
2. In your local terminal, run the following commands to link and push your code:
   ```bash
   # Add your remote origin URL (replace with your repository's URL)
   git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY_NAME.git
   
   # Rename default branch to main (if not already)
   git branch -M main
   
   # Push your code
   git push -u origin main
   ```

*(Notice that your `.gitignore` file will automatically prevent committing the virtual environment `.venv/` and the massive `training_data/` dataset, making the push extremely fast and secure!)*

---

## ⚡ Option A: Deploy via Render Blueprint (Recommended - 1 Click!)

We have created a `render.yaml` file in the root directory. This contains the "Blueprint" or "Infrastructure as Code" instructions for Render to automatically build and configure your service.

1. Go to your **Render Dashboard** and click **New +** -> **Blueprint**.
2. Connect your GitHub/GitLab account and select your repository.
3. Render will read the `render.yaml` file and automatically populate the web service name, build commands, starting commands, and optimization environment variables!
4. Click **Approve** or **Deploy**.
5. *That's it!* Render will build and launch your application.

---

## 🔧 Option B: Manual Deployment

If you prefer to configure the service manually on the Render website:

1. Click **New +** -> **Web Service** in your Render Dashboard.
2. Connect your repository.
3. Configure the following settings:
   - **Name**: `deepfake-image-detector`
   - **Language**: `Python`
   - **Branch**: `main`
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `python image-detection-module/api/app.py`
   - **Instance Type**: `Free`

4. Expand the **Advanced** section and add the following **Environment Variables**:
   
   | Key | Value | Reason |
   |:---|:---|:---|
   | `PYTHON_VERSION` | `3.10.13` | Recommended stable Python version for TensorFlow |
   | `TF_CPP_MIN_LOG_LEVEL` | `2` | Suppress heavy TensorFlow warnings to save memory |
   | `TF_NUM_INTEROP_THREADS` | `1` | Limit TensorFlow thread allocation to save memory |
   | `TF_NUM_INTRAOP_THREADS` | `1` | Limit internal parallelism to fit in Render free tier |

5. Click **Create Web Service**.

---

## ⚠️ Free Tier RAM Constraints & Optimizations

TensorFlow is a resource-intensive machine learning library. Render's **Free Tier** offers **512 MB of RAM**. Importing TensorFlow and loading a neural network can push the RAM usage close to or slightly over this limit, which might cause an **Out of Memory (OOM)** error.

To avoid this, we have pre-configured several key optimizations:

1. **Lightweight Model Enabled**: The API starts by searching for `saved-models/deepfake_fast.h5` (11.5 MB) which utilizes a Transfer Learning framework (MobileNetV2 architecture). This uses substantially less RAM than custom CNNs.
2. **TensorFlow Environment Flags**: The `TF_NUM_THREADS` and log silencing in our blueprint actively prevent TensorFlow from spawning heavy threads that leak RAM.
3. **Waitress Integration**: The server is built with `waitress`, a production-grade wsgi server which is highly light and stable under constrained resources.

> [!TIP]
> **If you encounter OOM (Out Of Memory) Crashes during startup:**
> If you notice the deployment fails at startup with exit code `137` or standard out of memory warnings, we highly recommend upgrading the Render service to the **Starter Tier** (2 GB RAM, $7/month). It will run the image predictions instantly and safely.

## 🔍 Step 3: Verify Your Live App

Once Render shows **"Live"**:

1. Click on the unique URL generated by Render (e.g. `https://deepfake-image-detector.onrender.com`).
2. The browser will open the elegant Deepfake Image Detector UI.
3. In the top-right corner, look at the status indicator:
   - **🟢 Model Ready**: Both backend API and TensorFlow model loaded perfectly.
   - **🔴 Model Not Loaded**: The API is up, but the model file is missing or failed to initialize.
   - **🔴 API Offline**: The server is still restarting or crashed.
4. Upload an image, click **Analyze Image**, and view the real-time probability graph!
